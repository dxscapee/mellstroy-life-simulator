# ASSETS — текстуры сцены: как их подкладывать в игру

> Коротко: положил файл в `art/<объект>/<номер>.<расширение>` → ассеты собрались сами →
> перезагрузил страницу → объект на сцене одет в твою текстуру. Заглушка-прямоугольник
> исчезает, файла нет — прямоугольник остаётся. Видео и картинки поддерживаются на равных.
>
> Этот файл — единственная инструкция по ассетам. Структура проекта в целом — в `ABOUT_PROJECT.md`.

---

## 1. Как это устроено (одной картинкой)

```
art/<группа>/<стадия>.<ext>          ← ТВОИ МАСТЕРА (любое качество/размер; В GIT)
        │
        │  npm run assets   (или автоматически: npm run dev + Vite-плагин)
        ▼
public/assets/<группа>/<стадия>.<хеш>.webp|mp4|webm   ← СОБРАННЫЕ ассеты (НЕ в git — генерируются)
public/assets/manifest.json                           ← реестр: что на что подменять
        │
        │  игра читает манифест при старте
        ▼
сцена: прямоугольник-заглушка подменяется спрайтом той же геометрии
```

Три правила, из которых следует всё остальное:

1. **Папка = объект.** `art/house/` — дом, `art/world/` — фон улицы, `art/character/` — игрок.
   **У каждой сцены своя папка:** у игры ДВЕ сцены — улица (двор/дом/машина/игрок) и дом
   (игрок + рабочее место), между ними переключает кнопка сбоку. Поэтому у фона и у рабочего
   места появились «парные» папки: `art/world_home/` — фон КВАРТИРЫ, а мебель/камера/комп
   рисуются в домашней сцене из папок с суффиксом `_home` (`furniture_home`, `camera_home`,
   `pc_home`). Папки без суффикса (`furniture`, `camera`, `pc`) — уличные и в текущей сборке
   игрой НЕ используются: они оставлены заделом на уличную версию рабочего места.
2. **Имя файла = номер стадии.** `0` — базовая стадия, дальше `1`, `2`, `3` (сколько стадий у
   объекта — в таблице ниже). Файла для текущей стадии нет — берётся ближайшая **младшая**
   (поэтому сначала достаточно одного `0`).
3. **Расширение = формат.** `.png/.jpg/.jpeg/.webp/.avif/.gif` — картинка, `.mp4/.webm/.mov/.m4v` — видео.
   Внутри одной папки для одной стадии должен быть ровно один файл (иначе сборка скажет об ошибке).

`art/` (мастера) и `public/assets/` (результат) — **разные вещи**: мастера (`art/`) лежат в git, а результат (`public/assets/`) генерируется и в git НЕ хранится.
Руками в `public/assets/` ничего не кладём: папка собирается пайплайном (он же чистит устаревшее).

### Работа вдвоём / на втором компьютере (2026-10-04)

Раньше `art/` был в `.gitignore` — и второй разработчик после клонирования репозитория
не находил папку для текстур. Теперь мастера — часть репозитория (а собранное генерируется само):

1. `git clone` → папка `art/` уже есть со ВСЕМИ папками групп (их держит файл
   `art/<группа>/.gitkeep`, git пустые каталоги не хранит — не удаляй эти файлы).
2. Кладёшь свои текстуры → `npm run assets` (или просто `npm run dev`) → готовые ассеты
   обновятся в `public/assets/` локально; в git их нет — коммить нужно ТОЛЬКО мастер из `art/`.
3. Если у тебя нет мастеров какой-то группы (ты не рисуешь фон, а напарник рисует) —
   пайплайн НЕ ТРОГАЕТ её готовые ассеты и записи манифеста (в отчёте строка
   «группы без мастеров в art/: …»). Так прогон на твоей машине не стирает чужие текстуры.

| `pc` | Комп (улица) | **360×480** | 3 | видео/картинка | задел; сейчас не рисуется |
| `pc_home` | Комп (дом) | **360×480** | 3 | видео/картинка | ближний слой рабочего места |

Объекты-навыки (харизма, интеллект, юмор, эмоциональность) на сцене не рисуются — текстур для них нет.
Имена объектов СТАТИЧНЫ (не меняются от прокачки); столбец «Стадии» — это число визуальных
стадий-текстур, а не подписи в карточке.

Числа в таблице — **истинные габариты**: текстура рисуется ровно в этот бокс, а заглушка на
сцене подписана ровно этими числами («4 · ДОМ · 384×640»). Хочешь рисовать в 2 раза крупнее
для резкости — рисуй, пайплайн сам уменьшит (см. «maxScale» в §6).

Боксы выровнены по сетке 8px (2026-10-03): игрок 264×552 (было 330×690) — заметно ниже дома,
его высота = 1/3 причёски + 2/3 одежды = 552, ширина совпадает с полосами (264). Причёска и
одежда вместе **ровно** закрывают игрока.

Три слоя рабочего места **обязаны** быть одного размера (360×480) — они стоят друг
на друге; пайплайн проверяет это и ругается, если разъехались.

## 3. Быстрый старт

```bash
npm install            # один раз: подтянет sharp (конвертер картинок)

# 1) положил мастер, например дом:
#    art/house/0.png   (384×640, PNG/WebP/JPG — что удобнее)

npm run assets         # собрал: public/assets/house/0.<хеш>.webp + manifest.json
npm run dev            # игра: дом уже в твоей текстуре, подпись-заглушка исчезла
```

В режиме `npm run dev` шаг `npm run assets` делать **не обязательно**: Vite-плагин сам следит за
`art/`, собирает ассеты при появлении/изменении файла и перезагружает страницу. Ручная команда
нужна перед prod-сборкой/заливкой и когда dev-сервер не запущен.

## 4. Форматы

### 4.1 Картинки

| Что | Как |
|---|---|
| Поддерживается | PNG, JPG, WebP, AVIF, GIF (анимированный GIF тоже) |
| Прозрачность | нужна там, где объект не прямоугольный (игрок, носимые, машина, двор) — PNG/WebP с альфой |
| Что делает пайплайн | конвертирует всё в **WebP** (качество 88, альфа 100), уменьшает до капа размера (см. `maxScale`), никогда не увеличивает |
| Что НЕ делает | не режет и не растягивает под пропорции бокса — если соотношение сторон сильно не то, только предупреждает |

Пропорции важны: текстура объекта вписывается в бокс **растяжением**. Нарисовал дом 384×640 —
всё честно; нарисовал 384×500 — дом будет слегка приплюснут. Пайплайн скажет:
`house/0: соотношение сторон … ≠ эталона 384×640 — при показе текстура растянется`.
Допуск — 1%. Единственное исключение — **фон**: он не растягивается никогда, а закрывает
экран по принципу cover (непропорциональный кадр обрезается по краям симметрично).

Рекомендации (2026-10-03): `maxScale: 2` у **всех** групп — игра рендерит вплоть до DPR 2, поэтому
мастера рисуй в **2×** от бокса (например, игрок 660×1380) — пайплайн сам уменьшит до капа
(игрок — до 528×1104), и на retina-экранах всё будет резким. Раньше у крупных слоёв (фон, двор,
дом) стоял кап 1× — он выбрасывал половину деталей и давал «замыленный» фон.
В мастерсе фона это особенно важно: если экран PORTRAIT, а фон ЛАНДШАФТНЫЙ (аспект 1.48),
игра по cover растягивает его по ВЫСОТЕ (width-сторона режется). Поэтому рисуй фон минимум
~2560px по ширине, иначе cover-апскейл съест резкость.

### 4.2 Видео

| Что | Как |
|---|---|
| Основной формат | **MP4 / H.264**, `yuv420p`, без звука, с `-movflags +faststart` |
| Второй формат | **WebM / VP9** — обязателен, если нужна прозрачность |
| Прозрачность | **только WebM VP9 с альфой** (`yuva420p`) или MOV/HEVC с альфой. MP4/H.264 альфу НЕ поддерживает — прозрачные области станут чёрными |
| Не поддерживается | AVI, MKV, HEVC/H.265 в MP4 (Chrome не играет), звуковые дорожки (не нужны) |
| Что делает пайплайн | копирует файл как есть (не перекодирует! sharp видео не умеет), проверяет, что он вообще похож на видео, и предупреждает, если нет faststart |

Готовые команды — в §9.

### 4.3 Память и производительность

- Одна текстурная рамка 1120×759 в RGBA — это ~3.4 МБ видеопамяти/ОЗУ; при капе 2× фон
  2240×1518 — уже ~13.6 МБ. Пять таких видео, крутящихся одновременно, уронят слабый телефон.
- Игра держит ОБА фона текущей локации (улицы и квартиры): так кнопка сцен переключает
  сцену мгновенно и не перезапускает видео-декодер. При смене ЛОКАЦИИ старые фоны игра
  освобождает сама — то есть одновременно живут максимум два фона.
- **Держи одновременно 1–2 видео.** Хороший шаблон: видео — только фон ТЕКУЩЕЙ локации; объекты —
  картинки. Если хочется анимировать объекты — короткие зацикленные клипы 2–4 с, не 20 с.
- Пайплайн предупреждает в dev-консоли, если живых видео-текстур стало больше двух.
- Фон прошлой локации игра **освобождает** сама (видео-декодер при этом закрывается) — об этом
  думать не надо.
- Стартовый набор (фон + игрок + купленные объекты) грузится под загрузочным экраном; остальное —
  лениво, по мере надобности.

## 5. Пайплайн: команды и отчёт

```bash
npm run assets         # собрать один раз + валидация + отчёт (это и есть «проверка перед заливкой»)
npm run assets:watch   # следить за art/ и пересобирать на каждое изменение (F5 руками)
npm run dev            # то же, что watch, но ещё и с автоперезагрузкой страницы
npm run build          # tsc + vite build; перед сборкой ассеты обновляются автоматически
```

Пример отчёта:

```
[assets] Сборка ассетов — 30.09.2026, 14:03
  world/0        видео    —         1.5 МБ  из art/world/0.mp4
  house/0        картинка 384×640   5.3 КБ  из art/house/0.png
  house/1        картинка 384×640   5.4 КБ  из art/house/1.png
[assets] Итого: 3 файл(ов) по манифесту, вес папки 1.5 МБ — бюджет 90 МБ OK
[assets] Стартовый набор (world/0, character/0, house/0): 1.5 МБ — бюджет 15 МБ OK
```

Что пайплайн делает по шагам:

1. **Скаффолдит** папки `art/<группа>/` — структура готова всегда, даже если пусто.
2. **Сканирует** мастера. Ошибки/проблемы — в отчёт: файл с именем не по схеме, стадия больше
   допустимой, конфликт форматов на одной стадии, неподдерживаемое расширение.
3. **Собирает**: картинки → WebP с хеш-именем `<стадия>.<хеш>.webp`, видео → копия с хеш-именем.
   Хеш считается от содержимого и настроек, поэтому изменил файл — получил новое имя, а старое
   исчезнет (кэш браузера не подсовывает устаревшую картинку).
4. **Чистит** `public/assets/<группа>/`: удаляет файлы, которых больше нет в наборе.
5. **Пишет манифест** `public/assets/manifest.json` (только если что-то изменилось — без git-шума).
6. **Считает вес** и проверяет бюджеты: `90 МБ` на всю папку ассетов (лимит площадки — 100 МБ
   на всю игру) и `15 МБ` на номинальный стартовый набор. Превышение — ошибка (exit code 1).

Итог по кодам возврата: `0` — всё хорошо, `1` — есть ошибки (конфликты, превышен бюджет).

## 6. Настройки: `src/data/sceneAssets.json`

Этот файл — **общий** для игры и пайплайна: размеры и число стадий здесь, а не в коде сцены.
Изменил размер — поменялся и бокс на сцене, и требования пайплайна к мастеру.

```jsonc
{
  "version": 1,
  "sourcesDir": "art",           // откуда читать мастера
  "outputDir": "public/assets",  // куда писать собранное
  "webpQuality": 82,             // качество картинок (0–100)
  "webpAlphaQuality": 100,       // качество альфа-канала
  "budget": {
    "totalMB": 90,               // потолок веса всей папки ассетов
    "startupMB": 15,             // потолок «стартового набора» (см. ниже)
    "startupKeys": ["world/0", "world_home/0", "character/0", "house/0"]
  },
  "groups": {
    "world": { "label": "Фон", "w": 1120, "h": 759, "stages": 5, "maxScale": 2 },
    "house": { "label": "Дом", "w": 384, "h": 640, "stages": 4, "maxScale": 2 }
    // … остальные группы так же
  }
}
```

- `stages` — сколько стадий разрешено (файл с большим номером будет пропущен с предупреждением).
  Для объектов это число стадий из `objects.ts` (`tierNames`), для фона — число локаций (5).
- `maxScale` — во сколько раз текстура может быть крупнее бокса. `2` = «можно отдать 2× для
  резкости», `1` = «только 1×» (крупные слои).
- `startupKeys` — номинальный стартовый набор для бюджета (фоны обеих сцен 0-й локации, игрок,
  дом). Фактически игра грузит ФОНЫ ТЕКУЩЕЙ ЛОКАЦИИ и ВСЕ купленные объекты (включая те, что
  стоят в другой сцене) — бюджет по номиналу, грубый ориентир.

Запустил `npm run assets` после правки JSON — отчёт покажет результат.

## 7. Что происходит в игре

1. **Манифест.** При старте игра читает `public/assets/manifest.json`. Нет манифеста — игра
   спокойно живёт на заглушках (в консоли: `[assets] манифеста нет — сцена живёт на заглушках`).
2. **Стартовый набор.** Под загрузочным экраном грузятся: фоны ОБЕИХ сцен текущей локации
   (улицы и квартиры), тело игрока и все
   купленные сценовые объекты на их текущих стадиях. Потом вызывается `LoadingAPI.ready()` —
   платформа не должна показывать рекламу раньше, чем игра одета.
3. **Подмена.** Как только текстура готова, прямоугольник-заглушка (и его подпись) скрываются,
   вместо них — спрайт тех же габаритов. Раскладка при этом не меняется вообще.
4. **Ленивая загрузка.** Купил тачку — текстура подтянулась в фоне (секунду может быть заглушка;
   так экономим старт). Нет ассета для группы — заглушка остаётся навсегда, игра не падает.
5. **Тиры.** Вырос тир объекта — игра просит текстуру следующей стадии; не нарисована — остаётся
   предыдущая.
6. **Сцены.** Кнопка сбоку (внизу справа) переключает улицу и дом: игра меняет корень сцены
   (двор/дом/машина ↔ рабочее место) и ключ фона (`world/<локация>` ↔ `world_home/<локация>`).
   Ассета фона нужной сцены нет — видна тёплая заглушка-прямоугольник (при игре без мастера
   квартиры). Прокачка объектов при переключении НЕ меняется — уровни у сцен общие.
6. **Фон локации.** Сменилась локация — грузится `world/<index>` (ТОЧНЫЙ ключ, без отката вниз:
   нет ассета — заглушка); старая текстура освобождается
   (для видео это закрытие декодера).

### Отладка в dev-консоли

`npm run dev` кладёт в `window` три ручки:

```js
assets.count                    // сколько ассетов обещает манифест
assets.has('house/1')           // есть ли конкретный ассет
assets.resolveKey('house', 2)   // какой ключ реально будет показан для 2-й стадии
assets.texture('house/1')       // текстура из кэша (или null — идёт загрузка)
assets.release('house/1')       // освободить вручную (для проверки памяти)
scene.refreshTextures()         // руками пере-синхронизировать сцену с реестром
game.state                      // состояние игры как обычно
```

Полезно знать: `[assets] …` в консоли — это логи реестра (что нашлось, чего нет, что подменилось).

## 8. Сценарии

### 8.1. Первая картинка (например, дом)

1. Нарисуй дом 370×620 с прозрачным фоном.
2. Положи как `art/house/0.png`.
3. `npm run dev` (если сервер уже запущен — просто подожди секунду и обнови страницу).
4. В игре дом — твоя картинка, подпись «4 · ДОМ · 370×620» исчезла.

### 8.2. Ещё стадии

`art/house/1.png`, `art/house/2.png`, `art/house/3.png` → прокачай дом (в dev — дебаг-панель,
«+1 lvl всем» ×10) и увидишь смену текстуры на 10/20/30 уровнях.

### 8.3. Фон-картинка

`art/world/0.png` (1120×759). Фон всегда закрывает экран: если пропорции не 1120:759, игра
обрежет края по центру (cover), а не растянет — но лучше рисовать в эталонных пропорциях.

### 8.4. Фон-видео

```bash
ffmpeg -y -f lavfi -i "color=c=#123a6b:s=1120x758:r=25:d=6" \
  -vf "format=yuv420p" -c:v libx264 -preset slow -crf 23 \
  -movflags +faststart -an art/world/0.mp4
```

Положил `art/world/0.mp4` (файл `0.png` при этом удали — на одну стадию один файл) → фоном
крутится видео, без звука, без контролов, зациклено.

### 8.5. Видео у объекта

То же самое, но в папке объекта: `art/car/0.webm` — прозрачная анимация тачки (альфа — только
WebM VP9). Помни про лимит «1–2 живых видео».

### 8.6. Заменить/удалить текстуру

- Заменить: положил новый файл поверх старого (то же имя) → пересборка → новое хеш-имя, старый
  файл удалён. Кэш браузера не мешает.
- Удалить: убрал файл из `art/` → пересборка → ассет пропал из манифеста → на сцене снова заглушка.

### 8.7. Перед заливкой на Яндекс

```bash
npm run assets     # 0 код возврата = бюджеты в порядке, конфликтов нет
npm run build      # dist/ с ассетами и манифестом
```

Проверь: в отчёте нет строк `ОШИБКА`, вес папки ниже бюджета, никаких кириллических/пробельных
имён (пайплайн выдаёт хеш-имена латиницей — это его работа, руками имена не трогаем).

## 9. Готовые команды ffmpeg

**MP4 (непрозрачный фон, H.264, faststart, без звука):**

```bash
ffmpeg -i source.mov -vf "scale=1120:758:force_original_aspect_ratio=decrease,format=yuv420p" \
  -c:v libx264 -preset slow -crf 23 -movflags +faststart -an art/world/0.mp4
```

**WebM VP9 (второй формат или фон для Chrome):**

```bash
ffmpeg -i source.mov -vf "scale=1120:758:force_original_aspect_ratio=decrease,format=yuv420p" \
  -c:v libvpx-vp9 -crf 32 -b:v 0 -row-mt 1 -an art/world/0.webm
```

**WebM VP9 с прозрачностью (для объектов):**

```bash
ffmpeg -i source_with_alpha.mov -vf "format=yuva420p" \
  -c:v libvpx-vp9 -pix_fmt yuva420p -crf 28 -b:v 0 -row-mt 1 -an art/car/0.webm
```

**Зациклить и обрезать до 4 секунд:**

```bash
ffmpeg -stream_loop 2 -i raw.mp4 -t 4 -c copy art/pc/0.mp4
```

**Проверить faststart (moov должен быть в начале файла):**

```bash
ffprobe -v trace art/world/0.mp4 2>&1 | grep -m1 "type:'moov'"
```

Правила, которые проверяет/предполагает игра: `muted`, `playsinline`, `loop`, без звуковых дорожек,
без встроенных контролов. Размер кадра — по таблице §2 (чётный по обеим сторонам для H.264:
1120×759 → кодируй в 1120×758).

## 10. Требования Яндекс Игр (что важно для ассетов)

- **≤ 100 МБ** — все файлы игры в распакованном виде (бюджет пайплайна — 90 МБ, запас на код).
- **Никаких пробелов и кириллицы** в именах файлов/папок, которые уезжают в игру. У нас хеш-имена
  латиницей; кириллица допустима только в `art/` (локально, в архив не попадает).
- **Системный видеоплеер запрещён**: видео играется программно (скрытый `<video>` без контролов,
  `muted` + `playsinline`, автоплей). YouTube-вставки запрещены — только свои файлы.
- Элементы не должны обрезаться/наезжать друг на друга — это про UI, но и текстуры лучше рисовать
  в размер, чтобы не вылезали.
- Долгое нажатие не должно выделять текст/открывать контекстное меню — видео-элемент скрыт и
  `pointer-events:none`, канвас обрабатывает тапы сам.

## 11. Отладка: частые вопросы

| Симптом | Причина и что делать |
|---|---|
| Текстура не появилась | Проверь папку/имя/номер стадии (§2–3), запусти `npm run assets`, посмотри консоль: `[assets] …` скажет, чего нет. Возможно, объект не куплен (заглушки видны только у купленных). |
| В консоли `манифеста нет` | Собери ассеты: `npm run assets`. Пустая папка `public/assets/` (кроме manifest.json) — тоже норма, но тогда текстуры не откуда взять. |
| `Конфликт стадии world/0: «0.mp4» и «0.png»` | На одну стадию — один файл. Удали лишний. |
| `стадии 0..3 — файл не будет показан` | Номер стадии больше допустимого (§6, `stages`). |
| `соотношение сторон … ≠ эталона` | Рисуй в эталонных пропорциях: объект иначе растянется, фон обрежется по краям (cover). |
| Бюджет превышен | Сожми видео (VP9/H.264, короче, меньше кадров) или подними `budget` в `sceneAssets.json` (но помни про лимит 100 МБ площадки). |
| `sharp не установлен` | `npm install` (sharp — devDependency пайплайна, в бандл игры не входит). |
| Видео чёрное/с прозрачными дырами | MP4/H.264 не умеет альфу. Прозрачность — только WebM VP9 (`yuva420p`). |
| Видео стоит на первом кадре | Браузер отказал в автоплее (энергосбережение). Игра догоняет по первому тапу; в проде для видео используй muted+playsinline (у нас так и есть). |
| `лишний/занятый файл … не удалился` | Windows держит файл, пока его отдаёт dev-сервер (EBUSY). Не ошибка: уберётся при следующем прогоне (после перезапуска dev-сервера). На игру такие файлы не влияют — манифест на них не ссылается. |
| В `dist/assets/<группа>/` пусто, папок нет | Так и должно быть: папки групп создаются только под реально собранные файлы. |
| Текстура видна, но объект «двоится» / мелькает | Две вкладки dev-сервера пишут в `public/assets` одновременно — оставь один `npm run dev`. |
| Хочу посмотреть, что игра реально загрузила | `window.assets.count`, `window.assets.has('house/1')`, `window.scene.refreshTextures()` (§7). |

## 12. Расширение

- **Новая текстура/стадия** — только файлы + `npm run assets`. Кода не касаемся.
- **Новая локация** — файл `art/world/<номер>.<ext>` + при необходимости `stages` в JSON.
  Имена и порядок локаций задаёт `src/data/locations.ts` (5 шт., индекс = стадия world).
- **Новый сценовый объект с текстурой** — четыре шага: запись в `objectDefs` (`src/data/objects.ts`,
  с `tierNames`), группа в `src/data/sceneAssets.json`, строка в `OBJECT_ASSET_GROUP`
  (`src/data/assets.ts`), спека + build-метод + ветка в `applySceneState` (`src/view/GameView.ts`).
  Детали — `ABOUT_PROJECT.md`, §4.1.
- **Поменять размер текстуры** — `w`/`h` в `sceneAssets.json` (заглушка на сцене и требования
  пайплайна возьмут новое число). Перерисуй мастер под новый бокс.
- **Поменять качество/бюджеты** — там же, в `sceneAssets.json`.

## 13. Чего делать не надо

- Класть файлы прямо в `public/assets/` — папка генерируемая, пайплайн её чистит.
- Коммитить `public/assets/` (в т.ч. `manifest.json`) — папка генерируемая и намеренно НЕ в git.
- Править `public/assets/manifest.json` руками — перезапишется.
- Переименовывать собранные хеш-имена — игра ссылается на них из манифеста.
- Убирать `art/` из git или добавлять его в `.gitignore` (2026-10-04) — мастера ДОЛЖНЫ там быть:
  иначе второй разработчик клонирует проект и НЕ НАХОДИТ
  папку для текстур (именно так и случилось). Пустые папки групп держит `art/<группа>/.gitkeep`, структура описана в `art/README.md`.
- Заводить второй способ подгрузки текстур в обход `AssetRegistry` (прямой `Texture.from(url)` в
  сцене) — сломается ленивая загрузка, освобождение памяти и подсказки в консоли.
